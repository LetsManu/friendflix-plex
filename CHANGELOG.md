# Changelog

All notable changes, grouped by what you notice. Each release has its own section (`## [x.y.z] – Codename – date`, cut by the *Release* workflow); what is not released yet is listed under *Unreleased*.

## [Unreleased]

### Versions & releases
- **Heads-up: `latest` now only moves on releases; set FF_TAG=nightly to keep following main.** Until 1.1.0 every green commit on main also moved the `latest` image tag. Now main publishes `nightly` (plus the short sha) and never `latest`; a `vX.Y.Z` tag still publishes `X.Y.Z`, `X.Y`, `X` and, for the highest release only, `latest`. Images are still re-tagged from the scanned CI build, never rebuilt. `FF_TAG` picks the channel: `latest` = stable, `nightly`, or `1` / `1.1` / `1.1.0` to pin (docs/operations.md, "Release-Kanäle"; docs/setup.md, "Release channels").
- **Update channels in *Admin → Update*:** the page shows which channel the install actually runs: a release when its build sha is the commit of the `vX.Y.Z` tag (looked up on GitHub, cached like the update check), else a nightly build, shown as "1.1.0-nightly · abc1234" there, in the footer and in `GET /api/version` (new fields `build`, `channel`, `label`). A *Stable / Nightly* switch saves the new database setting `UPDATE_CHANNEL` (default stable, also under *Admin → Settings → Updates*): stable reports an update only for a newer release, with its notes; nightly reports newer commits on main. When the selected channel differs from the running one, or an update exists, the page shows the `.env` line (`FF_TAG=nightly` or `FF_TAG=latest`) and the pull command to copy. The switch takes effect only after that command: FriendFlix never touches Docker itself.
- **Fix:** image publishing sets `flavor: latest=false`, so `docker/metadata-action` can no longer add `latest` to a semver tag on its own (its default `latest=auto` does that for every plain release tag); only the explicit "highest release" rule moves `latest`, and a backport tag such as `v1.0.5` after `v1.1.0` never does.

### Discovering
- **Switch the recommendation engine in *Admin → Settings*:** `RECO_ENGINE` (v1 = the media server's similar lists, v2 = FriendFlix's own taste model, shadow = v2 computed beside v1 for comparison while everyone still sees v1), `RECO_EXPLORE` (exploration share 0–0.5, `0` = off), `RECO_HALF_LIFE_DAYS` and `POSTPLAY_ENABLED` are now normal database settings in the new group *Recommendations*, explained in all 7 languages. They apply on the next request without a restart; a value in `.env` still wins and locks the field. The expert tuning (`RECO_COEFFS`, the item index weights `RECO_W_*`) stays in `.env`, and the group says so. The recommendation card of the admin overview now says which engine is active and whether `.env` locks it (`GET /api/admin/reco` has a new field `locked`), with a *Change engine* link to the group. The home page cache key carries the engine, so a switch never serves the other engine's cached rows. Fix: long example addresses in setting hints wrap instead of widening the page at 320 px.

## [1.1.0] – Arancini – 2026-10-18

### FriendFlix for Plex (this fork)
- **FriendFlix 1.1 on Plex:** the post-play screen, recommendation engine v2, the player fixes, the account security fixes and the cast parity work of upstream 1.1 run on Plex, released as 1.1.0 like upstream.
- **Recommendation engine v2 on Plex:** the item index reads FriendFlix's mirror of the Plex library (`libraryFeatures`: genres, Plex labels as tags, studios, countries, up to 8 credited people, year, runtime, community and critics scores, Plex collections, summary and tagline; `libraryRoots`: an episode belongs to its show). Plex has no original language and no series status; those signals stay neutral. A title removed from Plex leaves the index at once. The engine card names v1 "classic" (on Plex v1 is FriendFlix's own genre and cast similarity).
- **Post-play screen on Plex:** *Episode N is still unwatched*, the next episode and collections work as everywhere; Plex keeps no series status and lists no announced episodes, so after the last available episode it always says *You're caught up* (never *finished*), without an air date or *Remind me*. Library access, age caps and kids profiles apply to every row.
- **Next episode on the TV with Plex:** the queued episode's token is bound to the cast it follows as upstream (180 s preload window, 120 s drain after a stop). Plex's own stream count lets its transcode start next to exactly that cast, its Plex session is reachable through the cast token only (never with the browser's cookie), and asking again ends the earlier queued transcode: never a stream past the role's limit. Plex may end a queued transcode that waits long; the sender then loads the next episode itself, as before.
- Docs: post-play, engine v2 and casting the next episode on Plex, with their known limits (docs/plex.md, English and German), README parity rows.

### Login
- **Fix: account security actions fail with "sign-in not reachable".** *Security → Change password* (and the other *Security* actions) looked the person up in Authentik with the service token first and answered `502` when Authentik refused that token (deleted, expired, another one in `.env`, or no *Can view User*); the dialog only said the sign-in service was not answering. The re-authentication now identifies with the account's e-mail address when the lookup fails (the end of the flow still checks the person by `sub`), and every failure has its own message: too slow, not reachable, FriendFlix's access refused, sign-in inside FriendFlix switched off, not set up. *Change* actions that cannot run here continue on Authentik's own settings page.
- **Sign-in card diagnostics:** *Admin → Status → Sign-in* now checks the service token (accepted or refused), each read permission the service account needs, and one call of the login flow from the server, and lists the last Authentik error of the past 24 hours as class, HTTP status and endpoint path (never a token, host or address). The backend log has the same fields.
- **Repair Authentik setup:** a one-click repair on the sign-in card re-applies the service account with every permission the current version needs (an install set up before the in-app sign-in never got the device-delete and two read permissions), creates a deleted service token anew and saves it, and imports the e-mail change flow once its mail template is mounted. It needs a one-time superuser token, which is never stored or logged. See docs/authentik.md section 3.6.
- **E-mail change in the wizard:** the setup wizard (and the repair) imports the e-mail change flow as soon as Authentik lists its mail template `friendflix-email-change.html`; without it the step is skipped and says why.
- **Change your username in FriendFlix:** *Security → Username* changes the Authentik username after a re-authentication, with Authentik's rules (letters, digits, `@ . + - _`, up to 150 characters), a check that nobody else has it, at most 3 changes a day and an audit entry. FriendFlix keeps knowing you by your account id, so the sign-in stays the same; where the provider uses the username as subject, the change is refused.

**Upgrade note (Authentik):** after updating, open *Admin → Status → Sign-in*. If it shows *Service token: Refused by Authentik* or a missing permission, run *Repair Authentik setup* with a one-time superuser API token (docs/authentik.md section 3.6) and delete that token afterwards. To offer the e-mail change, mount `deploy/authentik/templates/friendflix-email-change.html` (with your FriendFlix address in its link) under `/templates` on Authentik's server and worker first, then repair.

### Phone and TV
- **The remote screen while casting** shows what plays on the TV: the episode's artwork in the background, a card with the still, series, episode and device ("Playing via AirPlay" / "Playing on <TV>"), and one compact row with the device (change / reconnect) and Stop that never wraps, also at 320 px. At the credits the card turns into the next episode with its countdown, Cancel and Play now. Fullscreen is hidden while casting, the volume on AirPlay.

Chromecast queues the next episode on the receiver (its own token, which counts as a stream only once it plays), so the TV moves on even when the phone is locked; on AirPlay an end the sleeping page missed starts the next episode as soon as the page wakes. Fixes: a Chromecast that reset its time before reporting the end no longer drops the next episode (the receiver's idle reason decides), and a receiver draining the old episode's segments after a switch no longer counts as a second stream (which made the next token fail with "too many streams" until it was retried).

### Under the hood
- **Recommendation engine v2, fixes before the switch to `v2`:** concurrent recommendations share one load of the item index, which is reloaded after 5 minutes or once the index job finishes a pass. The nearest-neighbour search reads an inverted index and scores at most a few thousand titles instead of the whole library. The co-occurrence and transition tables have a single builder: one per process, a Redis lock across replicas, and a stale table is answered while one builder replaces it. They are built from library-level data only: a new optional media-server hook `libraryRoots()` maps episodes to series with the admin key, never with a viewer's token. A pair is shown only when at least 2 *other* accounts share it, so the viewer's own viewing no longer counts towards it. On the post-play screen under v2, "Same universe" needs only 1 title and "What people watch after X" only 2, so the rows v1 shows are not dropped. Visibility is checked before the post-play cache, so a title the profile may no longer see gives 404 even while the cache is warm. Browser and phone Back close the post-play screen and keep you on the title, the player behind it is out of the tab order, and *Not interested* → *Undo* restores the earlier thumb. The trending cap can no longer be raised above 10 %. A full index pass re-checks titles it did not see before deleting them. The index heartbeat never takes over another replica's lock. The v2 "Because you watched" row is cached and computed once per home build. Extra v2 home rows under 4 titles are hidden. See docs/discovery.md.
- **Recommendation engine v2, rollout (`RECO_ENGINE=v2`, still `v1` by default):** with `v2` the home "Because you watched" rows, `because-more` and the post-play rows (because, taste and the new "What people watch after X" row from `transitionsFor`) are answered by `recommend()`, and `rankRows` orders the home and post-play rows. Any v2 error falls back to v1 and is counted in `friendflix_reco_fallback_total{surface}`. Every v2 title carries a `reason`, shown as a short caption ("Because you watched X · same director") in all 7 languages; a tap opens "Why am I seeing this?". `friendflix_reco_plays_total{row,engine}` counts plays started from a recommendation; "Not interested" feeds `dismiss`. Profile setting **Reset my recommendations** (`POST /api/prefs/reco/reset`) forgets the cached taste vector and the row statistics. The admin overview shows click rate and play rate per engine (`GET /api/admin/reco`). Kids profiles are unchanged (age cap, no social or transition sources). Docs explain how to compare shadow with v1 and when to switch (gate, spec 4.7). Fix: the test for the digest's "send a test" endpoint pinned its clock, it failed on any day more than a week after its fixture date.
- **Recommendation engine v2, row ranker and exploration (still off by default):** a rule-based row ranker (`reco/rows.ts`) orders the rows of the home page and the post-play screen: continue watching first, one fixed slot for "leaving soon" or else "new", the other rows by how often this profile clicked and played each kind of row (small per-profile counters, no titles), rows under 4 titles dropped, no series you already watched, no row made only of series that are airing now (at most 1 in 3), and no friends, trending or next-up rows on kids profiles. Optional exploration `RECO_EXPLORE` (default `0` = off, `0.1` = about 1 title in 10 drawn from medium-score candidates, never the best 3) logs only aggregate counters per row kind (`friendflix_reco_explore_slots_total`, `friendflix_reco_explore_propensity_total`). `node scripts/reco-eval.mjs --ipw` replays a logged exploration policy with inverse propensity weighting. The new row kinds are accepted by `POST /api/reco/events`. See docs/discovery.md.
- **Recommendation engine v2, crowd signals, context and explanations (still off by default):** engine v2 now also uses what other accounts did, as aggregates only: item-item co-occurrence and "started right after finishing X within 7 days" transitions, built only from accounts with *share my viewing history* on and only for pairs that at least 2 different accounts share (no setting can lower that floor; the cached tables hold counts per title pair and no account, day or time). It reuses friends' ratings and recommendations (with their existing opt-ins), the trending aggregates of "This week with us" (capped at 10 % of the score on every surface) and the fresh labels (new series, new film, new season). Context works as soft multipliers, never filters: time of day, device class (anonymous start-time measurements, aggregated), language, runtime against the time left at this hour, and series status against how often the profile drops series. Every surface (post-play, because, taste, detail, home rows) has its own weight set; post-play weighs transitions and seed similarity most. Each recommended title carries a reason: the seed that contributed most plus up to two shared traits (director, lead actor, genre, studio, same universe, "people watch this next", "friends rated it"); friend names only as far as their opt-ins allow. Kids profiles never get co-watch, transition, friends or trending sources and always the age cap. For the post-play screen there is `transitionsFor()` (wired in a later step). `node scripts/reco-eval.mjs --ablation` shows which components move NDCG@10. The friends and trending queries moved to `backend/src/discoverData.ts` unchanged. See docs/discovery.md.
- **Recommendation engine v2, taste profile and scoring (shadow mode, off by default):** a new `backend/src/reco/` engine builds a positive and a negative taste vector per profile from thumbs, stars, completion, rewatches, favorites, the watchlist, dropped titles and early abandonment (under 15 % and no return for 14 days), with a recency half-life of 120 days, and scores candidates (Jellyfin similar titles, same collection or creator, nearest neighbours of the profile in the item index) with a weight set per surface (post-play, because, taste, detail, home rows), a smoothed community rating, freshness and penalties for seen, dropped and watchlisted titles. Thumbs-down titles and, on kids profiles, everything above the age cap are filtered; kids profiles never use social sources; titles are always resolved with the viewer's own token. Rows are re-ranked with MMR (lambda 0.7, at most 2 per collection, a cap per genre). `RECO_ENGINE=v1|shadow|v2` (default `v1`): `shadow` computes v2 next to v1 on "Because you watched", still returns v1 and only records `friendflix_reco_shadow_runs_total`, `friendflix_reco_shadow_overlap` and `friendflix_reco_shadow_score_delta` (bounded labels, no titles). `RECO_HALF_LIFE_DAYS` and `RECO_COEFFS` (JSON) override every coefficient. `scripts/reco-eval.mjs` now evaluates v2 next to the popularity, v1 and co-occurrence baselines and prints the v2 comparison and the NDCG@10 gate (`--gate`); it needs `npm run build -w backend` once. See docs/discovery.md.
- **Recommendation index (preparation for the new engine, nothing changes for viewers yet):** a background job builds an `item_features` index of your library (genres, tags, studios, top people, year, runtime, ratings, countries, collection, series status, and the 40 most telling words of the overview and tagline by TF-IDF) with IDF weights, so a rare director counts more than the genre "Drama". It needs no viewing data, refreshes a new title 30 seconds after it arrives and rebuilds fully every night at 3:00. New optional media server method `libraryFeatures` (capability `libraryFeatures`; Jellyfin implements it, no paths or tokens leave the server), field weights `RECO_W_GENRES`, `RECO_W_TAGS`, `RECO_W_STUDIOS`, `RECO_W_PEOPLE`, `RECO_W_TEXT`, `RECO_W_NUMERIC`, `RECO_W_COLLECTION`. *Admin → Status* shows the index size and age; metrics `friendflix_reco_index_items`, `friendflix_reco_index_age_seconds`, `friendflix_reco_index_runs_total{mode,result}`. Migration 41. See docs/discovery.md.

### FriendFlix for Plex (this fork)
- **Plex media server** behind the neutral interface: `MEDIA_SERVER=plex` selects `backend/src/plex/*` and the gateway adapter `gateway/src/upstream/plex.ts`; `compose.plex.yaml` connects the backend and gateway to an existing Plex server (address and token in the setup wizard or *Admin → Settings*; optional pins `PLEX_URL`, `PLEX_TOKEN` / `PLEX_TOKEN_FILE`). Preview: tested against a fake Plex server built from Plex Media Server 1.43 answers, not released.
- **One server-side Plex token**, held by the backend (the gateway gets it from the backend over the internal network, in memory only), sent as a header and never to a client. FriendFlix enforces roles, profiles, age limits and kids profiles itself, from a Postgres mirror of the Plex library (sync every 5 minutes, notification websocket, nightly sweep). No plex.tv accounts for friends, no Plex Pass needed.
- **Signed media paths:** part, transcode-session, trickplay and chapter-still paths carry an HMAC; the gateway asks the backend per item before it fetches. Plan B is not supported with Plex (`/internal/authz-nginx` answers `501 plan_b_unsupported`).
- **Blocks 15 to 18 on Plex:** cast & info (guest stars from the episode credits), chapters with stills (when Plex generates chapter thumbnails), picture-and-sound chips and the 4K / HDR filter from Plex stream details, fresh labels (season finale only for series known to be ended), leaving soon, story so far, themed lists, calm mode, admin shell; wishes use local request-service users. Playback info is not prefetched on hover with Plex (capability `playbackPrefetch: false`), because that call starts the Plex transcode. `/api/home` works unchanged on the Plex implementation.

The mirror gains tagline and rating-source columns (fork migration 4: movies and shows re-read their details once). Upstream's download fix (stuck at 99 %), the `/diagnose` page and the tab bar alignment come along unchanged.

The footer shows "FriendFlix for Plex 1.0.0 · Arancini"; `compose.plex.yaml` points the update check (`UPDATE_REPO`) at `LetsManu/friendflix-plex`. ### Streaming
- **Adaptive quality:** *Auto* picks the quality your connection can carry (the last estimate is remembered per device for 7 days), steps down after a stall or a network error and steps back up once the connection is steady.
