# Mehrsprachigkeit (i18n)

FriendFlix spricht Deutsch, Englisch, Französisch, Spanisch, Italienisch, Türkisch und Polnisch.
Deutsch ist die Quelle aller Texte und die Rückfallsprache. Die Umsetzung kommt ohne Zusatzbibliothek aus:
ein kleiner Svelte-Store plus `Intl` (PluralRules, DateTimeFormat, NumberFormat, RelativeTimeFormat, ListFormat, DisplayNames).

## Welche Sprache gilt?

1. **Profil**: jede Person wählt ihre Sprache pro Profil (Einstellungen → Sprache, Fußzeile, „Mein FriendFlix → Sprache“).
   Gespeichert in den Profil-Einstellungen (`profile_prefs.data.language`).
2. **Instanz-Standard**: von einem Admin festgelegt (`app_settings` Schlüssel `default_language`).
3. **Deutsch**, solange nichts gespeichert ist.

Erste Nutzung:

- Ein Admin (Hauptprofil) wird beim ersten Besuch einmal nach der **Sprache der Instanz** gefragt (Deutsch vorausgewählt).
  Hat das Admin-Profil selbst noch keine Sprache, wird dieselbe Wahl auch dafür gespeichert.
- Jedes Profil ohne gespeicherte Sprache sieht beim ersten Login die Vollbild-Auswahl **„Sprache wählen“**.
  Vorausgewählt ist die Browsersprache (falls unterstützt), sonst der Instanz-Standard. „Später“ speichert den
  Instanz-Standard, damit die Frage nicht wiederkommt.

Der Browser merkt sich die zuletzt genutzte Sprache (`localStorage` `ff-locale`), damit die Oberfläche schon vor der
Antwort von `/api/me` in der richtigen Sprache erscheint. `<html lang>` folgt immer der aktiven Sprache.

Wann wird die Seite neu aufgebaut?

- **Start**: Die Sprache aus `/api/me` wird angewendet, **bevor** die Seite montiert wird (das Layout wartet auf den
  Sprach-Chunk). Rendert das Layout früh (Boot-Hinweis `ff-boot-hint`, siehe `lib/gate.ts`), wartet es auf die Sprache
  der letzten `/api/me`-Antwort (`lang` im Hinweis). Die Seite wird also genau einmal montiert – der Player startet nicht
  doppelt, keine Anfrage läuft zweimal.
- Weicht `/api/me` danach doch ab (Sprache auf einem anderen Gerät geändert), wird die Seite **nicht** neu aufgebaut:
  alle `$t`-Texte folgen sofort, per `tr()`/`fmt*()` im Skript berechnete Texte erst beim nächsten Seitenwechsel.
- **Wechsel durch die Person** (Fußzeile, Einstellungen, Erstauswahl → `saveLanguage`): die Seite wird einmal neu
  aufgebaut (`{#key $pageEpoch}` im Layout, `remountPage()`), damit auch Skript-Texte folgen. Seiten, deren Texte alle
  reaktiv sind, können das abschalten (`keepPageOnSwitch()` in `onMount`, z. B. die Einstellungen: ungespeicherte
  Eingaben bleiben erhalten).

Öffentliche Seiten ohne `/api/me` (Einladung `/invite/…`, Fernseher-Kopplung `/tv`): gemerkte Sprache → Browsersprache
(`navigator.languages`) → Instanz-Standard (`defaultLanguage` in der Antwort von `/api/invite/:token` bzw.
`POST /api/tv/code`), siehe `publicLocale()`. Die Sprache ist geladen, bevor sprachabhängige Daten (Kontotyp) geholt werden.

## Backend

| Endpunkt | Zweck |
| --- | --- |
| `GET /api/me` | `language` (wirksam: Profil → Instanz → `de`), `languageChosen` (Profil hat eine eigene Wahl), `defaultLanguage`, `defaultLanguageSet`, `suggestedLanguage` (aus `Accept-Language`, nur als Vorschlag) |
| `PUT /api/prefs/language` `{ language }` | setzt nur die Sprache des aktiven Profils (jedes Profil darf das) |
| `PUT /api/prefs` | volles Einstellungsobjekt; die Web-App schickt `language` **nie** mit. Fehlt das Feld oder ist es `''`, bleibt die gespeicherte Sprache erhalten (eine Formular-Speicherung kann keine anderswo getroffene Wahl zurückdrehen) |
| `GET/PUT /api/admin/settings/language` `{ language }` | Instanz-Standard (Admin, CSRF, Audit `settings.language`) |

Erlaubte Codes: `de en fr es it tr pl` (`backend/src/i18n.ts`, `LANGUAGES`).

### Backend-Texte (Benachrichtigungen, Push, ntfy/Discord, Wochenrückblick, Bezeichnungen)

Alle Texte, die der Server selbst formuliert, stehen in `backend/src/messages.ts`: ein flacher Katalog pro Sprache
(`'download.ready.title': 'Download bereit'`), Deutsch ist die Quelle, jede andere Sprache muss **jeden** Schlüssel haben
(Test `backend/test/i18n-messages.test.ts` prüft Schlüssel, Platzhalter und Pluralformen je Sprache). Platzhalter `{name}`
und Pluralobjekte (`{ one, few, many, other }`, Auswahl über `n`) funktionieren wie im Web.

Code verwendet nie fertige Sätze, sondern Nachrichten-Referenzen (`Text` in `backend/src/i18n.ts`):

```ts
import { m } from './i18n.js';
await notify(ctx, { userId, kind: 'download_ready', title: m('download.ready.title'), body: m('download.ready.body', { title: name }) });
```

- `m(key, params)` – Parameter dürfen selbst Nachrichten sein (`m('achievement.unlocked', { name: m('ach.critic.title') })`),
  Zahlen werden je Sprache formatiert, `{ date: iso }` als Datum + Uhrzeit.
- `{ join: [...], sep }` setzt mehrere Texte zusammen (Zeilen des Wochenrückblicks). Ein normaler String bleibt unverändert
  (Titel, Namen, Notizen von Personen).
- `msg(lang, key, params)` / `render(lang, text)` liefern den fertigen String.

In welcher Sprache?

| Ziel | Sprache |
| --- | --- |
| Glocke / Posteingang (`GET /api/notifications`) | Sprache des **lesenden** Profils – die Referenz wird in `notifications.msg` (Migration 27) gespeichert und beim Abruf gerendert; `title`/`body` enthalten zusätzlich den Text in der Kontosprache (ältere Einträge ohne `msg` bleiben wie gespeichert) |
| Web Push | Sprache des Profils, zu dem das Abo gehört (sonst Instanz-Standard); andere Profile als das Hauptprofil bekommen weiterhin nur „Neue Benachrichtigung“ in ihrer Sprache |
| eigenes ntfy-Thema, Wochenrückblick-Inhalt | Kontosprache (Sprache des Hauptprofils → Instanz → Deutsch) |
| Broadcasts, globales ntfy, Discord | Instanz-Standard → Deutsch |
| `roleLabel` in `/api/me` | Sprache des aktiven Profils; `/api/invite/:token?lang=xx` (die Einladungsseite schickt ihre Sprache mit, sonst Instanz-Standard; die Antwort enthält `defaultLanguage`). Über `ROLES_JSON` umbenannte Rollen behalten ihren Namen; `/api/admin/roles` meldet dafür `builtinLabel` (nur dann übersetzen die Admin-Seiten, `lib/roles.ts`) |
| Download-Qualitäten (`/api/downloads/options`) | Sprache des aktiven Profils |
| Gerätenamen („Chrome auf Linux“, „Fernseher (TV-Modus)“) | Kontosprache beim Anlegen des Geräts (gespeicherter Name) |

Nicht übersetzt werden vom Server: Wochentag und Achievement-Namen in `/api/stats` (die Web-App übersetzt sie über den
Schlüssel), Fehlercodes (`{ error: 'not_found' }`, die Web-App zeigt eigene Texte) und `prep.error` von Downloads (nur
Codes `prep_failed` / `prep_gone`, wird nicht angezeigt). Posteingangs-Einträge, deren Schlüssel inzwischen umbenannt
oder entfernt wurde, zeigen den beim Anlegen gespeicherten Text statt des Schlüsselnamens (`renderKnown`). Text korrigieren: Eintrag in `backend/src/messages.ts` ändern; neue Sprache: Katalog dort ergänzen.

### Offline (Service Worker)

Der Build schreibt `/_app/locales.json` (Sprache → Chunk-Dateien, Vite-Plugin in `web/vite.config.ts`). Die Seite merkt sich
ihre Sprache zusätzlich im Cache `ff-meta` (`web/src/lib/sw/locale.ts`, `localStorage` ist für den Service Worker nicht
lesbar). Bei der Installation einer neuen Version legt der Service Worker die Chunks dieser Sprache mit in den Cache,
damit `/offline` auch nach einem Update ohne Netz in der gewählten Sprache erscheint. Deutsch steckt ohnehin in der App.

## Dateien

```
web/src/lib/i18n/
  index.ts          Store, t/tr, Formatierer, LOCALES, setLocale (Import: '#lib/i18n')
  types.ts          Translation<…>, PluralForms, KeysOf
  rich.ts, Rich.svelte   sichere Mini-Auszeichnung (<b>, <kbd>, <a href="/…">)
  locales/de/<bereich>.ts   Quelle (typisiert, `as const`)
  locales/<sprache>/<bereich>.ts   Übersetzung desselben Bereichs (darf Schlüssel auslassen)
  locales/<sprache>/index.ts       fasst die Bereiche einer Sprache zusammen (ein Chunk pro Sprache)
web/src/lib/sw/locale.ts           merkt die Sprache für den Service Worker (Offline-Cache)
backend/src/i18n.ts, messages.ts   Sprachauswahl und Texte des Servers
web/src/lib/LanguageGate.svelte    Erstauswahl (Profil) und Instanz-Abfrage (Admin)
```

Bereiche (eine Datei pro Bereich und Sprache, damit parallel gearbeitet werden kann):

| `shell` | Layout, Kopfzeile, Profilmenü, Tab-Leiste, Kategorien, Fußzeile, Hilfe, Gerätefreigabe, Menü-Links |

| `admin` | Admin-Rahmen (Navigation, Übersicht/Dashboard, Aktivitäts-Sätze `admin.activity.*`) und bisherige Admin-Seiten |

## Benutzung

In `.svelte` (reaktiv, wechselt sofort mit der Sprache):

```svelte
<script lang="ts">
  import { t } from '#lib/i18n';
</script>
<h1>{$t('account.settings.title')}</h1>
<button aria-label={$t('common.close')}>…</button>
<p>{$t('shell.mobile.forName', { name: who })}</p>
```

In `.ts` (nicht reaktiv; erst aufrufen, wenn der Text gebraucht wird, nie auf Modulebene):

```ts
import { tr } from '#lib/i18n';
error = tr('common.saveFailed');
```

Schlüssel sind typisiert (`TKey`): ein Tippfehler ist ein Fehler in `npm run typecheck`. Für Schlüssel, die erst zur
Laufzeit entstehen, gibt es `trDynamic(key)`; besser sind Konstanten vom Typ `TKey` (siehe `lib/menu.ts`).
Listen mit Beschriftungen speichern den **Schlüssel** und übersetzen beim Anzeigen (`{$t(label)}`).

### Platzhalter und Mehrzahl

- `{name}` wird durch den Parameter ersetzt; Zahlen werden passend formatiert (`1.234` / `1,234`).
  Unbekannte Platzhalter bleiben sichtbar stehen.
- Mehrzahl: der Wert ist ein Objekt mit Formen, ausgewählt über den Parameter `n` mit `Intl.PluralRules`:

```ts
meUnread: { one: 'Mein FriendFlix, {n} neue Benachrichtigung', other: 'Mein FriendFlix, {n} neue Benachrichtigungen' },
```

`other` ist Pflicht. Mögliche Formen: `zero` (für n = 0 in jeder Sprache, optional), `one`, `two`, `few`, `many`, `other`.
Polnisch braucht `one`, `few`, `many`, `other`; Türkisch nur `other` (und optional `one`).

### Formatierer (aktuelle Sprache, alles über `Intl`)

| Funktion | Beispiel de / en |
| --- | --- |
| `fmtDate(d, opts?)` | 12. Oktober 2026 / 12 October 2026 |
| `fmtDateTime(d, opts?)` | 12.10.2026, 18:05 / 12 Oct 2026, 18:05 |
| `fmtTime(d, opts?)` | 18:05 |
| `fmtNumber(n, opts?)` | 1.234,5 / 1,234.5 |
| `fmtRelative(d, now?)` | gestern, vor 3 Stunden / yesterday, 3 hours ago |
| `fmtDuration(sekunden)` | 1 Std. 52 Min. / 1 h 52 min (Muster in `common.duration`) |
| `fmtList(items)` | Deutsch, Englisch und Japanisch |
| `intlLocale()` | `de-DE`, `en-GB` … für eigene `toLocale…String`-Aufrufe |

Nie `'de-DE'` fest eintragen. Sprachnamen von Ton-/Untertitelspuren liefert `langLabel()` (`lib/langs.ts`) in der UI-Sprache.

### Text mit Auszeichnung

Texte dürfen `<b>…</b>`, `<kbd>…</kbd>` und `<a href="/intern">…</a>` enthalten, wenn sie mit
`<Rich text={$t('shell.help.deviceD')} onLink={…} />` (`#lib/i18n/Rich.svelte`) ausgegeben werden. Alles andere bleibt
reiner Text – eine Übersetzung kann kein HTML einschleusen. Kein `{@html}` für Übersetzungen. Links müssen mit genau
einem `/` beginnen (kein `//`, `/\`, keine Leer- oder Steuerzeichen).

Mit Platzhaltern (Titel aus Metadaten, Codes aus der URL …) immer `<Rich key="detail.info.title" params={{ name }} />`:
die Werte werden erst nach dem Zerlegen der Auszeichnung als reiner Text eingesetzt und können nie zu Markup werden.

## Neuen Text hinzufügen

1. Schlüssel in `locales/de/<bereich>.ts` anlegen (sprechende, verschachtelte Namen, z. B. `detail.cast.title`).
2. Im Code `$t('detail.cast.title')` bzw. `tr(…)` verwenden.
3. Englisch in `locales/en/<bereich>.ts` ergänzen (Prüfung: der Typ erlaubt nur existierende Schlüssel).
4. Andere Sprachen dürfen fehlen – dann erscheint Deutsch.

## Übersetzung korrigieren oder Sprache ergänzen

- Korrigieren: Text in `locales/<sprache>/<bereich>.ts` ändern. Platzhalter (`{name}`, `{n}`) unverändert lassen.
- Neue Sprache: Eintrag in `LOCALES` (`web/src/lib/i18n/index.ts`, Code, Eigenname, BCP-47-Tag), Lader in `LOADERS`,
  Ordner `locales/<code>/` (Kopie von `locales/fr/` als Vorlage), Code in `backend/src/i18n.ts` (`LANGUAGES`, `LANGUAGE_TAGS`)
  und ein vollständiger Katalog in `backend/src/messages.ts`.

## Rückfallregeln

1. Text der aktuellen Sprache,
2. sonst Deutsch,
3. sonst der Schlüssel selbst (in Entwicklung und Tests mit Warnung `[i18n] missing key "…"` in der Konsole).

Fehlt eine Pluralform, wird `other` genommen. Kann ein Sprach-Chunk nicht geladen werden (offline, nicht im Cache),
bleibt die bisherige Sprache aktiv.
