# Cast bar – keep casting while browsing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While a title plays on a TV via AirPlay or Chromecast, the app stays usable with a cast bar docked at the bottom; Play on another title switches the TV, and tapping the bar reopens the remote (the watch page) for the running session.

**Architecture:** A new singleton `castEngine` (`web/src/lib/cast/engine.ts`) owns everything that must outlive `/watch/*` while casting: the `castSession` store, the cast token, progress reports, the Chromecast calls (`lib/cast.ts`) and, for AirPlay, the Player's own `<video>` element (moved into `document.body`) plus its existing AirPlay controller (`lib/player/airplay.ts`, rebound to the engine). `Player.svelte` hands a running cast over (`adopt`) and afterwards only renders a remote driven by `castSession`; `CastBar.svelte` in the root layout shows the session everywhere else. Play buttons call `playOrCast()`, which switches the TV instead of navigating.

**Tech Stack:** SvelteKit 3 / Svelte 5 (legacy component syntax), TypeScript strict, Vitest (Node, fakes for browser APIs), Playwright (Chromium; Safari AirPlay and the Cast SDK are faked).

**Spec:** `docs/superpowers/specs/2026-10-13-cast-bar-design.md`

## Review Focus

1. **The moved `<video>` still carries the Player's Svelte listeners** (`on:play`, `on:pause`, `on:ended`, `on:timeupdate`, … are not removed when the Player unmounts; Svelte only removes window/document listeners). After leaving `/watch/*`, pausing or ending on the TV must produce exactly one engine report, never a second `start`/`progress`/`stop` from the dead Player. Test in Task 4 (`only the engine reports after leaving the watch page`).
2. **Two Play taps on different titles in quick succession while casting:** the last tap wins, exactly one cast token stays live (all others revoked), the bar shows the last title, no `start` report for the loser. Tests in Task 2 (`last playOnTv wins`) and Task 3 (`airplay: last switch wins`).
3. **429 / `max_streams` / rate limit (10 per minute) on a switch:** one request per user action, error toast, state `reconnect` (one retry only from a tap on the bar); never an automatic retry loop. Test in Task 2 (`a failed switch does not retry`).
4. **The cast session ends (TV off, another phone takes over) while a switch is in flight:** the freshly issued token is revoked, `castSession` becomes `null`, no `start` report is sent. Test in Task 2 (`session-end during playOnTv revokes the new token`).
5. **A shared scene link `/watch/<same id>?t=120` while that title is cast:** the Player attaches (no new token, no `/api/playback/info`) and seeks the TV to 120 s instead of restarting. Test in Task 5 (`same title with ?t= seeks instead of restarting`).
