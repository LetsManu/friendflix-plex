## 1. How earlier ports were done

- **Always `git merge upstream/main`, never cherry-pick.** The merge is done on a `claude/sync-*` branch with a descriptive merge commit, for example "Merge upstream/main (cast bar, request service rename, Block 22 admin care, …) into the fork". The commit body lists every conflict and how it was resolved. One or more follow-up commits then adapt Plex (`feat(plex): Block 22 admin care on Plex …`, `fix(i18n): empty-video hint names Plex in the fork`, `test: fork brand in upstream's new push and admin tests`). The result goes to the fork's `main` as a PR, and the PR body is kept in `/home/user/pr-fork{3,4,5}.md`. Each body has: Summary (upstream sync line plus "only conflicts were …"), the Plex implementation of the new seam parts, "server-agnostic parts checked on Plex", docs, and a test plan (lint, typecheck, web/gateway/backend counts with Postgres, locked build plus full e2e, gitleaks on the PR range, unchecked real-Plex items).
- **Recurring conflict hotspots:** `README.md`/`README.de.md` (env table, quick start, privacy bullets, trademark notice), `.env.example`, `backend/src/config.ts` (PLEX_* next to upstream fields), `docs/architecture.md` (seam section), `CHANGELOG.md`, `.gitleaksignore`, `web/src/lib/admin/banner.test.ts` (fork says "Plex" in hints), push/notify (BRAND_NAME import), `.github/dependabot.yml` (stays deleted).
- **Conventions that held:** fork migrations in their own table (`plex_schema_migrations`), so upstream `db.ts` MIGRATIONS stays identical. Upstream e2e specs run unchanged, because the mocks are server-agnostic. Seam additions stay optional, and the fork implements them in `backend/src/plex/*`. Every port adds a check that no Plex token, Plex URL or `X-Plex-Token` appears in a response. `package-lock.json` is checked with `npm install --package-lock-only`. A fork CHANGELOG entry and `docs/plex.md`/`docs/de/plex.md` rows are added.

## 3. Seam gaps: where upstream assumes Jellyfin

Most of the new code goes through `ctx.jf` as upstream promised ("Plex fork must keep compiling, seam members optional"). Plex `MediaAdmin` identities are synthetic DB rows (`plex_identities`, `plex_media_policies` with ON DELETE CASCADE, `plex_userdata`), so most of it simply works. The gaps:

### 3.1 Block 23 phase 1 (admin users)
- `routes/adminUsers.ts jellyfinLinkOk()`: an active user calls `ctx.jf.views(user)` (works on Plex). A locked user needs the optional `admin.identityExists`, which **Plex lacks**, so the link shows `null` (unknown). **Gap, cheap:** add `identityExists: (id) => select 1 from plex_identities where id=$1`.
- Lock/unlock, access-until expiry, role change, per-user limit overrides, bulk actions, repair (`reapplyAccount` → `applyRole` → `applyPolicy`), approvals → `provisionUser` → `createIdentity`, activity tab (`ctx.jf.history`): all through `MediaAdmin`/`MediaServer` and supported by Plex. Verify with fork tests that `limits.ts` overrides reach `plex_media_policies` (max_streams/max_bitrate/max_height/download) and that PlexLimits enforces them.
- UI labels are already neutral (`adminPeople.detail.overview.jellyfin` = "Media server"). The `linked.jellyfin` key name in the API is internal and acceptable.
- `pollJellyfinSessions` → Plex `externalSessions()` returns `[]`. OK.

### 3.2 Block 23 phase 2 (self-service)
- **Deletion step 1, "media server identities"** (`deletion.ts`): `deleteIdentity` for each `jellyfin_ids` entry. On Plex this deletes `plex_identities` (policies cascade) and `forgetIdentity` deletes `plex_userdata`. It is idempotent ("already gone counts as deleted"). No gap. Add a Plex test: after the final deletion no `plex_identities`/`plex_media_policies`/`plex_userdata` rows remain for the account's identities. Check whether `PlexLimits` KV/session maps keyed by identity need a purge (transient, so low priority).
- **Export** (`export.ts historyOf`): pages `ctx.jf.history(user, {start, limit: 200})` with a 40-item overlap that assumes Jellyfin merges `resume` into page 0. Plex `history()` already includes in-progress items in one ordered set and honours `offset`/`limit ≤ 200`, so dedup handles the overlap. No code gap. Add a Plex export test with more than 200 history rows (truncation and partial flags) and check that the export JSON holds no `/library/`, `X-Plex-Token` or Plex URL.
- Restore within grace → `setDisabled(false)` (Plex upsert). OK. Account page/devices/re-auth are server-agnostic.

### 3.3 Block 25a (settings in DB)
- **Registry media keys:** `mediaSettings()` only has `JELLYFIN_URL`/`JELLYFIN_ADMIN_API_KEY`. The fork adds `PLEX_URL` (kind `url`, probe `media`, `runRequired: c => c.MEDIA_SERVER==='plex'`, apply `live`) and `PLEX_TOKEN` (kind `secret`, `secret: true`, same probe/runRequired). Encrypted at rest and never returned by `/api/admin/settings` (value `null` for secrets). `CREDENTIAL_DESTINATIONS` derives PLEX_TOKEN → [JELLYFIN_URL, PLEX_URL] automatically, so changing PLEX_URL needs re-auth. Correct, if a little broad.
- **Admin → Settings shows every kind's media keys.** There is no per-kind filter, so a Plex instance would list the Jellyfin fields too. **Gap:** hide media defs whose `runRequired(cfg)` is false when another kind's defs apply (in `routes/adminSettings.ts` GET and save validation, or a `visible: (cfg)=>…` on the def). This is an upstreamable seam fix.
- `config.ts` `MEDIA_REQUIRED` hard refusal goes away. A Plex instance without PLEX_* now starts in setup mode, as upstream intends. `backend/test/plex/config.test.ts` (asserts throws on missing PLEX_URL/TOKEN) must be rewritten: missing → setup mode/`runRequired` true. Keep `PLEX_TOKEN_FILE` read, and keep "Jellyfin default unaffected by empty PLEX_*".
- **`mediaUrlKey`** (`/internal/gateway-config`): with `MEDIA_SETUP.plex.urlKey = 'PLEX_URL'` it returns the Plex URL. Without a provider it falls back to the first `url` def of the kind (also PLEX_URL). OK.
- **Gateway, two real gaps (the most important part of the port):**
  1. **The Plex token is no longer only in env.** `gateway/src/upstream/plex.ts` reads `PLEX_TOKEN`/`PLEX_TOKEN_FILE` from its own env, and `validatePlexEnv` refuses to start without PLEX_URL and a token. With settings in DB the token saved in the wizard or Admin → Settings never reaches the gateway, and the gateway would not even start on a no-.env install. Fix: (a) `validateConfig` must allow "neither set" (remote mode); (b) `/internal/gateway-config` answers, for kinds that need it, an extra `upstreamToken` (or `upstreamAuth: {PLEX_TOKEN}`) next to `upstreamUrl`, behind the existing `x-internal-secret`, `cache-control: no-store`, never logged. `remoteConfig.ts` keeps it in memory and exposes `token()`, and `createPlexUpstream({ token: () => envToken ?? remote.token() })`; (c) env still wins, as for the URL; (d) the rev header refetch makes a token rotation apply within one authz round-trip. Seam shape suggestion (upstreamable): `MediaSetupProvider.gatewayKeys?: string[]` (Plex: `['PLEX_TOKEN']`), so the route stays kind-neutral. This keeps "token never reaches clients": backend → gateway over the internal network only.
  2. **INTERNAL_SECRET from the bootstrap volume.** The Plex adapter's default `secret = envSecret('INTERNAL_SECRET')` only reads env or `_FILE`. Upstream's gateway now gets it via `internalSecret(env)` from `/run/friendflix-gateway/internal_secret`. On a new install the env var is empty, so HLS/part/trickplay/chapter signature checks throw `missing env INTERNAL_SECRET`. Fix: `server.ts`/`upstream/index.ts` passes the resolved secret into the Plex adapter (`createPlexUpstream({ secret: () => secret })`, or a `configure({secret, token})` hook on the Upstream). Test with `FF_GATEWAY_BOOTSTRAP_DIR`.
- `server.ts` and `ctx.ts`: the media instance is rebuilt on PLEX_* change (`swapMedia`: old `stop()`, new `start()` after setup). `PlexClient` with an undefined URL does not throw at construction. Good. **Risk:** pointing PLEX_URL at a *different* Plex server keeps the old mirror (`plex_items` rating keys, `plex_sync_state`). A cheap guard: on start, compare `/identity` `machineIdentifier` with a stored one and force a full resync (or refuse with a health issue).
- **Media probe for Plex** (needed for the setup step and the Admin → Settings "Test"): `MEDIA_SETUP.plex.probe({PLEX_URL, PLEX_TOKEN}, {fetchImpl})`:
  1. `httpUrl`, then `GET <url>/identity` with no token. Unreachable/404 → `unreachable`; this also gives the `machineIdentifier`.
  2. `GET <url>/library/sections` with the **header** `X-Plex-Token` (never in the query, so no URL with a token can be logged). 401 → `unauthorized`.
  3. `GET <url>/status/sessions` (admin-only, used by Block 22 care). 401/403 → `not_admin`, which is a hard block. Consider a softer `warning` if the fork supports non-owner tokens, but care/refresh need an admin token.
  Use `redirect: 'manual'`, the 5 s deadline from the probe runner, `byStatus`/`smallJson` from `probeKit`, and answer codes only. `probeConfigured('media')` already counts any media key.
- Bootstrap/compose differences:
  - `compose.plex.yaml`: add a `bootstrap:` image override (`friendflix-plex-backend`); otherwise it pulls upstream's image, which works but is the wrong image. Change `PLEX_URL: ${PLEX_URL:?…}` to `${PLEX_URL:-}` in backend and gateway (no required .env any more), keep `PLEX_TOKEN(_FILE): ${…:-}`, keep the `JELLYFIN_*: !reset null` resets, and keep `UPDATE_REPO` and `extra_hosts`. Header comments: the setup wizard is the default, env pins are optional, and the placeholder-host example stays (this is a docs-style comment, as before).
  - `compose.secrets.yaml` note about the `plex_token` secret: unchanged, but mention that a `_FILE` value locks the field in the wizard.
  - `scripts/backup-bootstrap.sh`: project name `friendflix` is fixed by `name:` in compose. Unchanged.
  - Docs: `docs/plex.md`/`de` gain "Setup wizard on Plex" (manual URL plus token, where to find the token, never pasted anywhere but the wizard) and "Existing installs" (PLEX_* in .env stay and show locked).

### 3.4 Block 25b (setup wizard)
- `MEDIA_SETUP` has only `jellyfin`. The fork adds `MEDIA_SETUP.plex = { kind: 'plex', keys: ['PLEX_URL', 'PLEX_TOKEN'], urlKey: 'PLEX_URL', probe }` in a new `backend/src/plex/setup.ts`, with **no `auto`**. Upstream's `media-setup-seam.test.ts` already tests "a provider without auto (the Plex fork's manual step)". `GET /api/setup/state` then answers `auto: null`, and the web shows only the manual form and `setup.media.noAuto`.
- i18n (7 locales): `settings.keys.PLEX_URL` / `settings.keys.PLEX_TOKEN` (label plus help). The fork also adjusts `setup.media.text`, `manualText` and `urlHint`, which upstream words as "API key" and "e.g. http://jellyfin:8096", to "address and token of your Plex server". **Rule:** no placeholder host in UI strings, so the urlHint describes it ("the address and port (usually 32400) at which backend and gateway reach Plex") without an invented IP. No Plex logo or Plex-styled button: plain text field labels only.
- **Can Plex do `auto` from username/password?** Technically yes, and backend-only. `POST https://plex.tv/api/v2/users/signin` (form `login`, `password`, optional `verificationCode` for 2FA; headers `X-Plex-Client-Identifier`, `X-Plex-Product`) returns `authToken`. Then `GET https://plex.tv/api/v2/resources?includeHttps=1` with that token, matching `clientIdentifier` to the server's `/identity machineIdentifier`, gives the server `accessToken` (correct for owner and shared accounts). `run()` returns `{PLEX_URL, PLEX_TOKEN}`, the route saves it through the probe, and the client only ever sees `{ok:true}`. So **it is compatible with "token never reaches clients".** It is **not recommended for this port**:
  - The password goes to plex.tv, a fixed third-party host, not the URL the admin typed. That breaks upstream's "credentials only reach the host that was typed in" principle and needs its own docs and review.
  - 2FA accounts need an extra code field (the `auto.fields` union has no `code`), which is a web change upstream avoided.
  - The account token is a full plex.tv account credential with no clean per-key revoke (device removal API unverified), so `revoke` would be best-effort or missing.
  - Plex steers third-party apps to the PIN/link flow (`/api/v2/pins` + app.plex.tv/auth), which needs a different seam shape (poll), not `auto.run`.
  - It cannot be verified without a real plex.tv account (the e2e/CI only have fakes).
  Recommendation: manual only now. File a follow-up for a PIN-link provider (needs `auto.kind: 'link'` upstream) if wanted. Cost estimate if forced: ~1 day including fakes, risk medium.
- Setup gate and first admin: the first sign-in provisions through `createIdentity` (Plex DB row). Plex `start()` (sync) is deferred until operational (`live.syncMedia()` every 5 s), so the first admin briefly sees an empty library until the first sync. Note it in docs.
- e2e: upstream `setup.spec.ts`/`admin-settings.spec.ts` mock Jellyfin keys and labels and keep passing (mock-driven). Add fork specs: `setup.plex.spec.ts` (mediaKind `plex`, keys PLEX_URL/PLEX_TOKEN, `auto: null` → no mode toggle, token field masked, test/save bodies) and the Admin → Settings media group on Plex (no Jellyfin rows once 3.3 is fixed). Extend the leak canary to a `PLEX_TOKEN` value.

## 5. Risks

- **Gateway token distribution** (Task 4) is a new secret path. Keep it internal-secret-gated, no-store, never logged, out of `/health`, and out of error messages. Prefer upstreaming `gatewayKeys` so later merges do not conflict in `internal.ts`/`remoteConfig.ts`.
- **INTERNAL_SECRET from the bootstrap volume** is easy to miss: unit tests pass with env secrets while production on a no-.env install fails all `/media` requests. Needs an explicit test with `FF_GATEWAY_BOOTSTRAP_DIR` and no env.
- **Existing installs:** PLEX_URL/PLEX_TOKEN from .env become "locked from environment". Removing `:?` from compose must not silently drop a configured token (`${PLEX_TOKEN:-}` passthrough stays).
- **Probe strictness:** `/status/sessions` → `not_admin` is a hard block. If any user runs a non-owner token today (the docs recommend a dedicated account), saves would be refused. Check what docs/plex.md promises before making it HARD, or map it to a warning.
- **Media swap at runtime:** a new PlexMediaServer per PLEX_* change restarts sync and the websocket. A changed server keeps a stale mirror (Task 8).
- **Test harness rewrite** (helpers.ts) touches every Plex route test. It is the biggest mechanical risk, so do it early (Task 5).
- **i18n drift:** the fork edits upstream setup strings to Plex wording, which will conflict at every later upstream change to `setup.ts`/`settings.ts` locales (a new hotspot).
- Plex `auto` is deliberately left out. If it is requested later, it needs a design review: third-party password handling, 2FA, and an unrevocable account token.
